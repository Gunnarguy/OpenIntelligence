# Inbound Message Templates

These are copy-paste templates for SideProjectors, email, DM, or founder-to-founder conversations.

Edit the bracketed sections before sending.

## 1. First Reply

Use this for normal inbound:

"Thanks for reaching out. The honest framing is that this is not a polished self-serve SDK yet. What exists today is the engine logic, the evaluation packet, the sample host app, and a real Apple-native path for ingestion, retrieval, citations, and verification behavior. If useful, I can do a short 20-minute call, show the exact demo, and then send the current packet if it looks like a fit."

## 2. First Reply If They Sound Like A Direct Buyer

Use this when they sound like they may buy the whole project:

"Thanks for reaching out. If you are looking at this as a direct asset buy, the cleanest path is a short call to confirm scope, then a brief diligence window with the current packet materials, and then repo transfer after paper and cleared payment. I can show you the engine, explain exactly what is included, and keep the process tight if it looks like a fit."

## 3. Qualification Message

Use this if they want details before a call:

"Helpful before we go deeper: 1) what documents do you actually need this to work on, 2) is your target product iPhone, iPad, Apple Silicon Mac, or a full repo acquisition, 3) are you exploring a feature, a pilot, a license, or a buyout, 4) do citations and trust review matter, and 5) if this is a buyout, what do you expect to receive besides the codebase?"

## 4. Post-Call Follow-Up

Use this after a good first call:

"Good talking. Based on the call, the honest next step is [paid evaluation / pilot / direct diligence]. I can send the current packet materials once we confirm the right sharing level. The core assets are the buyer packet, the partner packet, the demo host app, and the exact engine/code references behind them."

## 5. NDA Request

Use this when the conversation is serious:

"Before I send the deeper packet materials and get into non-public technical detail, I want to put a simple NDA in place. Once that is done, I can send the current evaluation packet, the companion buyer docs, and the exact references that show what is real versus what is still evaluation-stage."

## 6. Packet Send Message

Use this after NDA:

"Attached are the two current packet artifacts. The buyer packet is the current evaluation bundle around the engine. The partner packet is the companion doc set covering commitments, boundaries, process, and pricing. The honest framing is still evaluation-stage engine and codebase head start, not finished self-serve SDK productization."

Use with:

- `output/OpenIntelligence-SDK-Package/build/OpenIntelligenceEngine-Buyer-Packet.zip`
- `output/OpenIntelligence-Partner-Packet/build/OpenIntelligence-Partner-Packet.zip`

## 7. Direct Buyout Price Alignment

Use this when the buyer wants to buy the whole thing:

"If you want the full asset transfer path instead of a pilot, the current public asking price is $7,500. The clean version is: confirm scope, short diligence, simple transfer paper, cleared payment, then repo and packet handoff. If that range works, I can send the exact diligence materials and handoff checklist next."

## 8. Direct Buyout Scope Confirmation

Use this before paper:

"Before we finalize, I want to make the transfer scope explicit. My default assumption is: full repo, current docs, benchmark tooling, staged evaluation packet, and sample app materials. I do not assume App Store accounts, signing assets, domains, or ongoing support are included unless we write that down explicitly."

## 9. Handoff Scheduling Message

Use after payment is in motion:

"Once payment clears, I will deliver the repo transfer or archive, the current packets, the handoff checklist, and a short handoff call so you know exactly what is included and what still needs cleanup. I will also give you the commit reference used for transfer so the package is pinned to a known state."

## 10. Post-Payment Handoff Message

Use once transfer is complete:

"Transfer is complete. You now have the repo, the current packet artifacts, and the supporting docs. The most important files to read first are the engine inventory, the current limitations, the claims guardrails, and the handoff checklist. Please confirm repo access and receipt of the packet artifacts so we can close the loop cleanly."
