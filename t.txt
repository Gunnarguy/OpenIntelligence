## 🛠️ Phase 1: Environment Setup

Use **VS Code Profiles** to prevent extension conflicts and "bugging out."

**Action:** Settings (Gear) → Profiles → Create Profile

---

### 🧱 Domain A: The iOS "Heavy Lifter" Stack

*Profile: "iOS Architect"*

*Use when:* Building apps, UI work, Core Data, Swift logic

| Extension | ID | Why You Need It | Configuration Note |
| --- | --- | --- | --- |
| SweetPad | `sweetpad.sweetpad` | **The Engine.** Replaces Xcode for Build/Run/Simulate. | Critical: Must pair with `xcode-build-server` to feed build data to Copilot. |
| Swift (Official) | `sswg.swift-lang` | **The Brain.** Provides the LSP (IntelliSense). | Disable its "debug" features if you use CodeLLDB to avoid conflicts. |
| CodeLLDB | `vadimcn.vscode-lldb` | **The Scalpel.** Debugger that actually works with Swift binaries. | Requires lldb configuration in `.vscode/launch.json`. |
| SwiftFormat | `vknabel.vscode-swiftformat` | **The Enforcer.** Auto-formats code on save. Essential for teams. | Set `editor.formatOnSave: true`. Prevents "nitpick" comments in PRs. |
| SwiftLint | `kiro.git-swiftlint` | **The Police.** Highlights bad code patterns (force casts, huge functions) inline. | Requires `brew install swiftlint`. Shows errors in the "Problems" tab. |
| Apple Dictionary | `fiatjaf.vscode-apple-dictionary` | **The Reference.** Hover over a word to see Apple glossary definitions. | Minor but helpful for obscure API terms. |

**🚀 Setup Command (Run in Terminal):**

```bash
brew install xcode-build-server xcbeautify swiftlint
code --install-extension sweetpad.sweetpad
code --install-extension sswg.swift-lang
code --install-extension vadimcn.vscode-lldb
code --install-extension vknabel.vscode-swiftformat
code --install-extension kiro.git-swiftlint
```

### ⚙️ The "Glueware": Workspace Settings

Extensions are useless if they aren't configured. Paste this into `.vscode/settings.json`:

<aside>
📋

**iOS Specifics**

`"swift.path": "/usr/bin/swift"`

`"swift.sourcekit-lsp.serverPath": "/usr/bin/sourcekit-lsp"`

`"[sweetpad.build](http://sweetpad.build).xcodeWorkspacePath": "YourApp.xcworkspace"`

`"sweetpad.format.swiftFormatPath": "swift-format"`

**Formatting & Linting**

`"editor.formatOnSave": true`

`"editor.codeActionsOnSave": { "source.fixAll.swiftlint": "explicit" }`

`"[swift]": { "editor.defaultFormatter": "vknabel.vscode-swiftformat" }`

**Cognitive Load Reducers**

`"errorLens.fontStyleItalic": true`

`"errorLens.gutterIconsEnabled": true`

`"todo-tree.tree.showScanModeButton": false`

`"todo-tree.general.tags": ["TODO", "FIXME", "BUG", "HACK", "XXX"]`

**Copilot Context Optimization**

`"github.copilot.editor.enableAutoCompletions": true`

`"files.exclude": { "**/.git": true, "**/.DS_Store": true, "**/DerivedData": true, "**/build": true }`

</aside>

## 📜 Phase 2: The Constitution

Create this file at `.github/[copilot-instructions.md](http://copilot-instructions.md)` in **every repository**. This hard-wires the rules into the Agent.

<aside>
🤖

**🤖 Copilot Universal Constitution**

**1. Prime Directives (STRICT)**

- **Context First:** Before generating code, you MUST read [`ROADMAP.md`](http://ROADMAP.md) (for current status) and [`ARCHITECTURE.md`](http://ARCHITECTURE.md) (for patterns).
- **Zero-Sprawl Policy:** You are PROHIBITED from creating new text/markdown files (like [`plan.md`](http://plan.md), `update_[log.md](http://log.md)`) to document your work.
- **Single Source of Truth:** All task tracking must happen in [`ROADMAP.md`](http://ROADMAP.md). All technical notes must be inline code comments.
- **Silent Alignment:** Do not explain that you are following these rules; just follow them.

**2. iOS & Swift Standards**

- **Build System:** This project uses SweetPad and xcode-build-server. If builds fail, analyze `compile_commands.json`.
- **Frameworks:** Prefer SwiftUI. Use `async/await` for concurrency.
- **Architecture:** Follow patterns in [`ARCHITECTURE.md`](http://ARCHITECTURE.md). If undefined, default to MVVM with Protocol-Oriented dependency injection.

**3. Pipeline & DevOps Standards**

- **Idempotency:** Scripts must be re-runnable without side effects.
- **Secrets:** NEVER hardcode credentials. Use `$(Variable)` syntax.
- **Docker:** Use multi-stage builds (builder vs runner).

**4. Agent Mode Behavior**

- **Plan:** Propose your plan in the Chat window only.
- **Edit:** Apply changes directly to code files.
- **Verify:** Run a build/lint check before confirming done.
- **Update:** Check off the task in [`ROADMAP.md`](http://ROADMAP.md) (`[x]`) immediately upon completion.
</aside>

## 🏛️ Phase 3: Code Archaeology

Run these prompts in **Agent Mode** (`@workspace`) to reverse-engineer documentation from your existing "guessed-my-way-through" projects.

### Prompt A: Generate [ARCHITECTURE.md](http://ARCHITECTURE.md)

> @workspace Perform a Deep Scan of this repository. I need to document what has been built.
> 

> 
> 

> Create a file named [`ARCHITECTURE.md`](http://ARCHITECTURE.md) containing:

> - **High-Level Goal:** What does this app/pipeline actually do?

> - **Data Flow:** How does data move from input to output?
> 

> - **Tech Stack:** List all libraries and frameworks used.
> 

> - **Key Components:** Identify the 'meat and potatoes' files and explain their purpose.
> 

> - **Design Patterns:** Identify patterns I used (even if inconsistent).
> 

> 
> 

> Be technical. Document the existing reality.
>

> 

> 
>

> 

> - [x] (List every major feature you find implemented)
> 

> 
> 

> **2. Technical Debt (The Cracks)**

>

>

### Prompt C: Add Directory Standards to [ARCHITECTURE.md](http://ARCHITECTURE.md)

Add this section manually so the Agent knows where files belong:

```markdown
## Directory Structure Standards
- `/App`: Entry points and configuration
- `/Features`: Grouped by domain (e.g., /Auth, /Dashboard) — each folder has Views, ViewModels, Models
- `/Core`: Shared utilities, Networking, Extensions
```

## 🧹 Phase 5: Cleanup Protocols

### The Janitor (if Agent creates junk files)

> Agent, you violated the Zero-Sprawl Policy.
> 

> - Scan the file tree for any markdown files created outside of the core architecture of the app (exclude [`ROADMAP.md`](http://ROADMAP.md), [`ARCHITECTURE.md`](http://ARCHITECTURE.md), and [`README.md`](http://README.md)).
> 

> - If they contain useful info, merge it into [`ARCHITECTURE.md`](http://ARCHITECTURE.md) as a bulleted list.
> 

> - DELETE those temporary files immediately.
> 

> - Confirm when the file tree is clean.
> 

### The Housekeeper (organize messy file structure)

> Agent, strictly audit the current file structure against the 'Directory Structure Standards' in [`ARCHITECTURE.md`](http://ARCHITECTURE.md).
> 

> 1. Identify files in the root or generic folders that should be moved to specific Feature or Core modules.
> 

> 2. Propose a file move plan (e.g., move `UserView.swift` → `/Features/Auth/UserView.swift`).
> 

> 3. Upon my approval, execute the moves and update any project references to ensure the build doesn't break.
> 

> 
> 

> Goal: A clean root directory containing only configuration files.
>
