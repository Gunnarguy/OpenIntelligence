# Change Impact Document Update Workflow

This playbook defines the maintenance workflow for keeping documentation in sync after code changes or PR merges.

## Workflow Steps
1. **Analyze Diff**: Run `git diff --name-only HEAD`, which lists staged and unstaged changes against the last commit. On `main`, where this repository's work normally lands, `git diff --name-only main...HEAD` compares `main` with itself and prints nothing. On a branch, such as the cloud branch merged in `206e044`, also run `git diff --name-only main...HEAD`, because `HEAD` alone shows only uncommitted files. Add `git ls-files --others --exclude-standard` for new files not yet added. (Corrected 2026-09-29.)
2. **Identify Changed Files**: Extract the list of modified source files.
3. **Map to Required Docs**: Pipe the list into `scripts/required_docs.sh` (for example `{ git diff --name-only HEAD; git ls-files --others --exclude-standard; } | scripts/required_docs.sh`, which includes new files not yet added). It prints one line per requirement, `required` or `advisory`, the document, and the path that triggered it, and it maps Swift source and `fastlane/metadata*` paths only. It is the enforcing copy of the path-to-doc table in `.agents/rules/01-docs-and-notion-sync.md`; read that rule for the rows no script enforces (for example "any phase or milestone completion"). `documentation_cross_reference.csv` is an audit snapshot whose generator is not in the repository (`AGENTS.md` rule 16), so it is not the mapping source. `[evidence_level: code_verified, confidence: high, evidence_source: scripts/required_docs.sh header and table; output of printf 'OpenIntelligence/Services/Storage/EvidenceThreadStore.swift' piped into it, 2026-09-29]`
4. **Identify Impacted Docs**: Determine which markdown files document the modified subsystems or components.
5. **Update Only Impacted Docs**: Modify the identified documentation files to reflect the new code reality. 
6. **No-Docs-Needed Justification**: A written justification does not replace the documents the pre-commit hook requires: `scripts/enforce_docs_hook.sh` fails a commit whose staged Swift lacks the documents `scripts/required_docs.sh` names for its paths. A justification is for changes outside those paths only. `[evidence_level: code_verified, confidence: high, evidence_source: scripts/required_docs.sh, scripts/enforce_docs_hook.sh, corrected 2026-09-28]`
7. **Evidence & Confidence**: Include the required `evidence_level` and `confidence` scores for all documentation impact decisions.
