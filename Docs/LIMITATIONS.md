# Limitations

OpenIntelligence ships on the App Store for iPhone, iPad, and Mac, with paid subscription tiers. It is a real product, and the limits below are the honest boundaries of what it does well — not a disclaimer that it is a prototype.

> **Corrected 2026-08-05.** This document previously opened by calling the app "experimental software... a proof-of-work repository and prototype" and listed "It is not production-ready" and "It is not a commercial product offering" as limits. Both were false: the app has been selling `pro_monthly`, `pro_annual`, and `lifetime_cohort` through StoreKit since v4.4, and `README.md` states it is shipping. A limitations document that understates what the product is undermines the limits that actually matter, which are the safety and technical ones below.

## Product Limits

- It is not a finished enterprise SDK, and `OIEngine` still routes through app-owned services rather than standing alone.
- It is not a sealed binary SDK or a buyer-ready handoff.
- Building from source requires Xcode and Apple-platform development familiarity. Using the shipped app does not.
- Quality modes are not equally proven. Standard has a measured accuracy baseline. Deep Think has been benchmarked, but not in a way that separates it from Standard, and Maximum has no valid figure. See the Technical Limits below. **Corrected 2026-09-29:** from 2026-08-05 this line read "Standard has a measured accuracy baseline; Deep Think and Maximum do not."

## Safety Limits

- It is not validated for regulated workflows.
- It is not intended for clinical, legal, financial, or safety-critical decision-making.
- It is not a clinical decision-support system.
- It is not a diagnostic tool.
- It does not guarantee complete, correct, or exhaustive answers.

## Technical Limits

- Retrieval quality depends on document quality, extraction quality, and query scope.
- OCR, layout parsing, chunking, and entity extraction can fail or lose context.
- Citations indicate supporting sources, not formal proof.
- Confidence signals are engineering aids, not certified reliability metrics.

- AFM 3 Core Advanced — Apple's 20B sparse on-device model announced at WWDC26 — is real, but it is OS-managed. An app cannot select it: in the release SDK (Xcode 27.0, `27A266a`) `SystemLanguageModel` construction still accepts only `.default`, a `UseCase` (`.general`/`.contentTagging`, a task selector, not a size selector), or a LoRA adapter, and the adapter initializer is obsoleted in iOS 27. An app can observe which on-device model it has, in two ways. The same SDK has `SystemLanguageModel.variant` (iOS 27.0, macOS 27.0), which reads `.core3` or `.coreAdvanced3`; Apple's reference pages name them "AFM 3 Core" and "AFM 3 Core Advanced". And every response names its assets: each `Transcript.Response` in a response's `transcriptEntries` carries `assetIDs`, public since iOS 26.0 and documented as "Version-aware identifiers for all assets used to generate this response." OpenIntelligence reads neither, so it labels the local route as On-Device rather than asserting a parameter count. - **In the one corpus measured, Standard's on-device evidence filled roughly a quarter of the model's window.** Standard reads the window from `SystemLanguageModel.default.contextSize` rather than assuming 4096, but it sizes its evidence in characters, converting its token budget at 1.4 characters per token. A 10,000-character ceiling sits above that conversion and cannot bind at a window of 8192, where the conversion yields at most 9,756 characters; questions the app classes as trivial are held to 2,500 characters. 1.4 is close to what a dense table of part numbers and measurements costs (1.38 measured), and English prose costs far less per character (4.2 to 5.5 characters per token measured). In the Mac benchmark run `sourceonly-after-greedy25` of 2026-09-23 (25 research-paper cases, on-device, window read as 8192 in every case) the evidence sent was 3,177 to 9,494 characters, median 9,324. The assembled prompts were not saved. The same length of each case's recorded chunk text counts as 723 to 2,158 tokens, median 1,993, by the model's own tokenizer, so the token figures are an estimate from like text and the character figures are exact. Structured answer generation was skipped in all 25: that path is gated at 3,600 estimated tokens whatever the window is, and every skip logged an estimate of 4,247 or more. Deep Think and Maximum give their reasoning sessions fixed character budgets that are not derived from the window: 3,500 or 3,000 characters in the reasoning chain, cut to 2,200 once a session carries earlier findings, and 2,500 in Maximum's own loop. Two of their budget helpers do read the window. ## Demo Limits

Demo flows should use generic sample documents. Do not use private credentials, employer material, hospital-specific material, patient data, or sensitive personal data in public examples.
