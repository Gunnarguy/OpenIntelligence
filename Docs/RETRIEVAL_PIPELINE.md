## 1. Overview
The retrieval pipeline is the core engineering idea in OpenIntelligence: answers are grounded in user-provided material and expose the exact evidence that influenced them. The app is built to bias responses toward groundedness, showing uncertainty when evidence is weak rather than inventing confident prose.

    QueryPlan --> EmbeddingGen[Generate Query Vector - Core ML or Core AI]

    EmbeddingGen --> HybridSearch[Hybrid Search: FTS5 Lexical + Vector Similarity]
    GPUProfile --> HybridSearch
    HybridSearch --> RRF[Reciprocal Rank Fusion - RRF]
    RRF --> Cutoff{Adaptive Ceiling Cutoff}

    Rerank --> Floor[Dynamic Similarity Floor, after a wider search or a keyword retry when the first is weak]
    Floor --> MMR[MMR Diversity Selection, lambda from the library settings]
    GPUProfile --> MMR
    MMR --> ContextExpand[Context Sibling Expansion - ParentDocumentService]
    ContextExpand --> PackChoice{Lookup question, not step-by-step?}
    PackChoice -- Yes --> LeadWhole[Best passage whole as S1, then question-relevant sentences]
    PackChoice -- No --> LostInMiddle[Passages in Lost-In-Middle order, step-by-step ones in document order, then Needle Rescue]
    LeadWhole --> Evidence[Post-Retrieval Evidence + Exact Token Budgets]
    LostInMiddle --> Evidence
    HybridSearch -.-> Trace[[RetrievalTraceCollector - eval runs only, nil in production]]
    RRF -.-> Trace
    Cutoff -.-> Trace
    Rerank -.-> Trace
    Evidence -.-> Trace
    Trace -.-> StageScore[[Per-stage recall@k / MRR / nDCG - RetrievalStageEvaluator]]
    Policy[Persistent Picker Policy: Hybrid / On-Device / PCC] --> ModelRoute
    Evidence --> ModelRoute{ModelExecutionPlanner v2}
    Capability[Signed Entitlement + Availability + Quota + Consent State] --> ModelRoute

    ModelRoute -- Local --> LocalLLM[SystemLanguageModel.default]
    ModelRoute -- PCC Candidate --> Minimize[Minimized Cloud Evidence Envelope]
    Minimize --> Consent{Consent Valid?}
    Remembered[Canonical Remembered Consent - No Launch Prompt] --> Consent
    Consent -- Yes --> PCCLLM[PrivateCloudComputeLanguageModel]
    Consent -- No / UI Unavailable --> LocalLLM
    LocalLLM --> Verification[Verification Gates A-I - Negation & Word-Overlap]
    PCCLLM --> Verification
    Verification --> Decision{Every Gate That Ran Passes? Gate E runs only with embeddings}
    Decision -- Yes --> GroundedAnswer[Render Grounded Answer with Citations]

    Labelled --> RouteBadge

## 3. Pipeline Stages

1. **Import**: Files enter through Apple platform document workflows.
2. **Extraction**: Text, layout, and metadata are extracted.
3. **Chunking**: Chunks are generated with metadata using semantic and structure-aware rules, applied to word counts. A cut goes, in this order of preference, at the start of a section, at the end of a table or before a transition phrase ("However,", "In conclusion,"), when one lies within the size limits, and otherwise near the target size, at a sentence end within 100 characters of it or else between words. The phrases are the semantic part, and the code preset leaves them out. The target and overlap come from the library's chunking plan when it has one, and otherwise from the file's preset: 240 and 45 words for a PDF, an image or a CSV file, 180 and 35 for code, and 260 and 50 for other text. Either way they are never more than 260 and 50, and the ceiling is 310 words. Every library the app makes adapts itself (`autoAdaptDimension`) until the person turns that off in Library Settings, and a library saved before the setting existed reads it as off. An adapting library writes a plan from each file's opening text before it cuts the file (a PDF's first ten pages, or a file that reads as UTF-8 text), and that plan always asks for 280 words or more with an overlap of 50 or more, so in such a library every file is cut at 260 and 50 once a plan exists, and the plan's kind can turn the phrases on for code too. An image, an Office file or a PDF with no text layer gives no opening text and writes no plan, so it is cut by the library's last plan, or by its preset when the library has none. A library set by hand uses the two values chosen in Library Settings. A passage of under 15 words is merged into the one before it, with no size check, so a merged passage can pass the ceiling. A table stays one passage only up to 380 words, a larger one is split, and each table also gets a summary passage. A passage over 430 WordPiece tokens is split again. The embedding-based topic boundaries described at the top of `SemanticChunker.swift` never run: the app cuts with `chunkText`, from a chunker made without an embedding service, and `chunkTextAsync`, the only path to `detectEmbeddingBoundaries`, is called only by a test. ## A library's search settings (added 2026-10-20, for 5.7)

Library Settings has a Search section: a style (Automatic, Balanced, High Precision, Technical Manual, Exploratory) and, under Advanced Controls, the four values a style sets. Through 5.6 the styles were not shown and the controls sat behind `SettingsStore.developerRAGTuningEnabled`, which the app forces off, so a library's values were whatever it was created with or tuning after an import picked (`RAGService.autoTuneRetrievalConfigIfNeeded`). What each value does, read from the code on 2026-10-20:

- **Minimum score** (`RetrievalConfig.minSimilarity`). Standard's filter starts from it (`RetrievalPolicyService.filteringDecision`), and compares it with the re-ranker's score, which is relative: the cross-encoder's scores for one question are rescaled to 0.1 to 0.9 and then lowered for tables of contents, question banks and bibliographies (`RAGEngine.rerank`), so the best passage found scores high whether or not it matches well. Left to the app, the starting point is the lower of the library's minimum and the mode's (0.28, 0.25, 0.20), so a minimum between the mode's and 0.45 did nothing; chosen by the person, it is used as given. The filter then lowers it for a question whose best five passages average below it, for a lookup or keyword question (by 0.04, and by that rule to no lower than 0.18) and when the words don't match (`vocabularyMismatch`), raises it to 0.25 for a step-by-step question, and with nothing over it the answer is written from the closest passages (the acceptance override, or `reliabilityModeEnabled`). Find Passages applies the same minimum to the hybrid search's score, before any re-ranking, and never lowers it (`searchDocumentsRaw`), so a high minimum can leave it with nothing. Deep Think and Maximum pass their own minimum to every search they make: 0.05 for the first searches that build the pool, 0.03 for the precision lookup, and `RetrievalPolicyService.agenticMinSimilarity` for the rest. (Corrected 2026-10-20: this named `agenticMinSimilarity` for every search, and two pass a fixed minimum.) `[evidence_level: code_verified, confidence: exact, evidence_source: AgenticOrchestrator.swift:2205 (in executeMultiQuerySearch), RAGService.swift:10707, and AgenticOrchestrator.swift:1096, :1863, :2472, :2590, :6749, :8060, :8081]` `[evidence_level: grep_verified, confidence: high, evidence_source: grep -rn "executeFullRetrievalPipeline(" OpenIntelligence --include='*.swift', 2026-10-20: nine calls, each passing minSimilarity]`
- **Passages Needed** (`minConfidentChunks`). With 2 or more, a Standard answer is written only when that many of the passages it would use score at or over the minimum the person set, each at the score the re-ranker gave it (a rescued table passage is raised to just under the best score so it reaches the answer, and is not counted at that); otherwise the reply lists the closest three with their scores and how many made it (`strongPassageShortfall`, gating decision `high_accuracy_blocked`). Through 5.6 this acted only when the library's values equalled the High Accuracy preset exactly, and the acceptance override, set for nearly any library of ten or more passages, skipped it there, as did the lenient switch, which the app keeps off.
- **Exact words and meaning** (`vectorWeight`, `lexicalWeight`), in every mode. Each question moves them by up to 10 points by its kind, and each then stays between 35% and 65% (`QueryProfile.adjustedHybridWeights`), so High Precision's 75% acts as 65% on every question. The slider shows the stored value from 35% to 75%.
- **Variety** (`mmrLambda`), in every mode; Standard keeps at least 0.85 for a step-by-step question.
- **Citations** are not a setting: every mode asks the model for them (`RAGQualityMode.requiresCitations`), though an answer can still come back without one (with streaming or the reliability fallback on, `RAGService`), so the old "Require Explicit Citations" switch changed nothing and is not shown. Its stored field, `requireExplicitCitations`, now records that the person chose the values (`RetrievalConfig.isChosenByPerson`): the two places that read it already treated it so (the filter's starting point above, and tuning after an import, which leaves such a library alone, `RetrievalConfig.autoTuned`). The library's saved form and its iCloud copy are unchanged.

A library reads as Automatic while tuning after an import may still change it; one at a minimum of 0.5 or more that nobody chose (an older library's strict mode) reads as Custom, since tuning never changes it. A style is shown when the values equal its preset (within 0.001), so a moved slider reads as Custom; High Precision's 0.2 temperature cap follows the same test (`style == .precise`). Moving a control marks the library as chosen only when the value changes, so opening Advanced Controls changes nothing. Automatic picks Technical Manual when more than half of a library's documents are code, or at least two thirds (and two or more) are spreadsheets, and Balanced otherwise (`RetrievalConfig.recommended`). `[evidence_level: code_verified; test_verified (RetrievalStyleTests); measured (a robot run in the iOS 27.0 Simulator, 2026-10-20: a minimum of 70% with Passages Needed at 5 held back "How much is the pet deposit?"); confidence: high for the mechanism, not measured on the retrieval benchmark]`

## Suggested questions

`Services/Query/UX/SuggestedQuestionsService.swift` writes the chips on the Chat tab's empty state.
It is retrieval-adjacent rather than retrieval: it reads chunks, never the index. Three paths,
in the order they are tried:

1. **The curated set**, for a library made only of sample documents. Hand-written questions that
   skip generation. Since 2026-09-14 a sample is recognised by *identity* (`sampleIdentity(for:)`):
   each canonical sample filename or a numbered copy of it (`<stem>-<digits>.md`, which managed
   storage produces when a filename collides). Before that the check was an exact filename match
   and one numbered copy switched the curated set off. **Updated 2026-10-20, for 5.7:**
   `curatedSampleQuestions(forFilenames:)` returns the questions of the samples the library holds,
   in the list's order, where `isSampleWorkspace(filenames:)` required all three; any other
   document returns nil and the library goes to path 2. The chat screen shows the list from the
   first frame (`ChatScreen.curatedSampleQuestions`), and its own older list of four, which came
   first whenever the architecture and Private Cloud Compute guides were both there under their
   own names, and so kept this set off the screen unless one of them was a numbered copy, is gone.
   Each question names the heading of its guide it was written from, pinned by
   `SampleQuestionHeadingsTests`.
2. **Model-written questions**, per document, at ingestion for user documents and on demand for
   a library whose bank is empty. Accepted only when at least two survive passage grounding.
3. **Template questions** from specifications, procedures, warnings, definitions and terms.
   Since 2026-09-14 these fail closed when the model is present: an empty model result shows no
   question rather than a raw template. They still ship on a device with no model, and a bank that
   holds no model-written question is rebuilt once per launch when the model becomes available
   (`shouldRebuildBank`), because the sample library's bank is built on first launch, when Apple
   Intelligence is least likely to be ready, and used to be kept forever. `isAcceptableTemplateTopic`
   rejects lone abstract words, article-plus-word phrases and runs of the document's own title, and
   the research templates key on `documentCategory == .scientificPaper` rather than the word
   "study" in a passage.

Sample duplicates are removed by `SampleDocumentManager.removeNumberedSampleCopies`, on every refresh
pass and only when the canonical file is also present.
