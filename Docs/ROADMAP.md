## 0. Blocking Before v4.6 Submission

- **Remove 3B/20B capability-card claims from the Settings UI (Open):** `LLMModelType.capabilityCard` still ships the tagline "Dynamic routing between on-device 3B Core, 20B Core Advanced, and massive PCC models," a `3B / 20B` chip, a `4K / 4K / 32K — 3B / 20B / PCC` context stat, and a footer promising scaling "from 3B parameters to massive PCC clusters." `SettingsView.swift:426` renders that tagline as live user-facing text. This contradicts the v4.6 release notes, `Docs/LIMITATIONS.md`, and the v4.5.1 correction, and it is App Store-facing. The same card also asserts unbenchmarked figures (`< 0.8 s` TTFT, `≈65 tok/s`, `Zero-retention`). `[evidence_level: code_verified, confidence: exact, evidence_source: LLMModelType.swift:146,207-219, SettingsView.swift:426]`
- **Relocate the repository out of iCloud-synced `~/Documents` (Open):** RISK-20 is now reproducing as hard failures. iCloud writes `com.apple.FinderInfo` and `com.apple.fileprovider.fpfs#P` onto built tokenizer bundles, so `codesign` aborts with "resource fork, Finder information, or similar detritus not allowed" and the test build fails. Separately, `.git/refs/heads/main 2` and `.git/index 2` are iCloud conflict copies of a branch ref and the git index. Building with `-derivedDataPath` outside `~/Documents` works around the first; only relocation fixes the second. `[evidence_level: build_verified+code_verified, confidence: exact]`
- **Signed device, Archive, and TestFlight PCC validation (Open):** unchanged and still the substantive release gate. See the three `Validate:` items in the Notion engineering roadmap and the 35 scenarios in `Docs/AUDIT/PCC_DYNAMIC_ROUTING_TEST_MATRIX.csv`.

## 1. Near Term

- **Phase 9 Route-Evidence Gates (Implemented 2026-07-28):** `RouteEvalMetrics` scores `ModelExecutionReceipt` chains against six invariants covering route attestation, fallback attribution, fail-closed quota handling, and attempt-chain integrity, alongside per-route latency and fallback accounting. This closes the route half of Phase 9; the answer-quality half was already implemented in `RAGEvalMetrics`. Scoring is receipt-only, so it applies unchanged to simulator, device, and TestFlight data. `[evidence_level: code_verified+test_verified, confidence: high, evidence_source: RouteEvalMetrics.swift, RouteEvalMetricsTests.swift]`
- **Execution-receipt fidelity (Open, owner decision):** two receipt-construction gaps found during the Phase 9 work. `RAGService.swift:14691-14707` builds partial-stream receipts whose `completedTarget` names a route whose only attempt `.failed`, with no `fallbackReason` — a consumer reading `completedTarget` alone would believe the route cleanly completed. Separately, both `LLMService.swift` sites (`:831`, `:946`) record a single-element attempt chain, so a PCC attempt that failed before fallback survives only as a `fallbackReason`, not as an attempt. Routing semantics are a Tier-2 boundary; these are reported, not changed. `[evidence_level: code_verified, confidence: high]`
