## 2. Concrete technical claims per session: models, PCC terms, and Apple's recommended practices

### Takeaway
At WWDC26 Apple described a rebuilt on-device model: "better at logic and tool calling", better at instruction following, and able to take image input. It gave no parameter count, language list or benchmark for it in any session. It opened a PCC server model to third-party apps: 32K context (`contextSize` 32768), three reasoning levels, no token cost, a per-user daily limit, and eligibility limited to App Store Small Business Program members under 2 million first-time downloads. Apple's retrieval guidance is to hand the model a search tool rather than pre-stuffing context: SpotlightSearchTool, focused guidance on-device, fresh sessions per query. Its context guidance is to measure with `contextSize`, `tokenCount(for:)` and `usage`; drop completed tool calls; use rolling windows and summaries through dynamic profiles; split work across sessions; and evaluate every change. For untrusted retrieved text, Apple shows "spotlighting" delimiters in `historyTransform`.

**Retrieval: SpotlightSearchTool (session 246, the Core Spotlight articles and the sample)**
- Session 241 calls it "a search tool powered by Spotlight for implementing fully local Retrieval-Augmented Generation… by leveraging a Spotlight index and specially processed queries". The SOTU calls it "a new RAG tool powered by Core Spotlight that's private to your app" — [documented, fetched 2026-09-26; beta era] [241](https://developer.apple.com/videos/play/wwdc2026/241/), [102](https://developer.apple.com/videos/play/wwdc2026/102/)
- The tool runs on iOS, iPadOS, macOS and visionOS (not watchOS). It is a `Tool` conformer: "the model will invoke the tool with a generated query, Spotlight will execute that query and return a description of the result set back, and the model will reason over that output". It provides "semantic search over text" and "structured search over metadata, like dates, persons, locations" — [documented, fetched 2026-09-26; 246] [246](https://developer.apple.com/videos/play/wwdc2026/246/)
- A text-content limit: "some metadata in the Spotlight index, like text content and HTML, is stored in a highly-compact representation that can be searched, but not recovered in a way that a language model can read it". The fix is the new `CSSearchableIndexDelegate.searchableItems(forIdentifiers:)`, which returns full items and can "set any additional attributes on an item for the model to see". Apple says this lets the model "efficiently manage responses over potentially millions of results" — [documented, fetched 2026-09-26; 246] [246](https://developer.apple.com/videos/play/wwdc2026/246/)
- The model "may call SpotlightSearchTool more than once" per response. Results stream as batched replies on `tool.searchResults`, with a `queryToken` that tells the UI when to refresh. Reply content can be `.items`, `.scoredItems`, `.groupedItems`, `.count`, `.table`, `.statistic` or `.text`, each with "a handy LLM-generated label" — [documented, fetched 2026-09-26; 246] [246](https://developer.apple.com/videos/play/wwdc2026/246/)
- Guidance: "On-device models have a more restricted model context size, so it's best to use focused guidance". The options are `SpotlightSearchTool.GuidanceProfile(textMatch:dates:people:attributes:)` with `.dynamic(profile)`, or `.focused(.items)`. Custom `@Generable` `CustomStage` pipeline stages (for example a scoring stage) and a `ContactResolver` handle "I/me" — [documented, fetched 2026-09-26; 246 code] [246](https://developer.apple.com/videos/play/wwdc2026/246/)
- **The current article states a default-configuration fact and a hard failure mode**: "The default configuration of SpotlightSearchTool performs queries against your app's Spotlight index using all available search techniques and Private Cloud Compute (PCC) models designed for Apple Intelligence." It continues: "if you configure it to use the on-device language model without providing a `focused(_:)` guide, Spotlight search exceeds the context window of the model and can't return results." The article also offers a `compact` output format "if you're using a model with a small context window". Sources are `CoreSpotlightSource` (the app's index) and `FileSource` (indexed files in directories). With several sources, the tool "searches each source separately and then combines the results" — [documented, fetched 2026-09-26; current] [Making your indexed content available to Foundation Models](https://developer.apple.com/documentation/corespotlight/making-your-indexed-content-available-to-foundation-models)
- The article's `CustomStage` example is a `RecencyBoostStage` that outputs `.scoredItems`. Stages "can run in parallel", so design them "to run independently" — [documented, fetched 2026-09-26] [same article](https://developer.apple.com/documentation/corespotlight/making-your-indexed-content-available-to-foundation-models)
- Lab 8011: SpotlightSearchTool retrieval is "limited to your app's own sandbox". Another app from the same developer cannot pull donated content through the tool, even with a shared app group — [documented, fetched 2026-09-26] [8011](https://developer.apple.com/videos/play/wwdc2026/8011/)
- Evaluating retrieval: define samples with `expectedIdentifiers`, a `TrajectoryExpectation` with `ToolExpectation("searchSpotlight", …)`, and assert a "ResultCoverage" metric (the demo uses a ≥ 0.5 mean). Apple's closing line: "we're not writing search queries anymore. We're providing the content, and letting intelligence do the rest." — [documented, fetched 2026-09-26; 246] [246](https://developer.apple.com/videos/play/wwdc2026/246/)

**Context-window management and token budgeting**
- Session 242: dynamic profiles let you "trim or summarize the transcript to keep it within the model's context window". The session adds that "each model may have different context size limits… When moving between models, you may need to trim unnecessary entries", and that you can "improve the model's focus by removing irrelevant entries, or redact private information… when moving to a less private model" — [documented, fetched 2026-09-26] [242](https://developer.apple.com/videos/play/wwdc2026/242/)
- `historyTransform` is stateless and per request: "Transforms don't permanently mutate the session's transcript". The `@SessionProperty(\.history)` alternative "is lossy and its changes will be reflected across all profiles". The utilities package provides `.rollingWindow(size: .entries(10))` and `.droppingCompletedToolCalls()`. The summarization pattern runs `onResponse`: when `history.count > 50`, summarize the older part into a `@SessionPropertyEntry var summary` and inject it as `Instructions { "Summary: …" }` — [documented, fetched 2026-09-26; 242 code] [242](https://developer.apple.com/videos/play/wwdc2026/242/)
- KV cache: "appending to the transcript preserves the KV cache… If you rewrite history by removing entries, changing the attached tools, or updating the instructions, that will typically trigger a cache invalidation, and can increase latency." Rewriting history also risks accuracy ("it's possible to confuse the model") — measure it with the Instrument and the Evaluations framework — [documented, fetched 2026-09-26; 242] [242](https://developer.apple.com/videos/play/wwdc2026/242/)
- Tool calling mode is `ToolCallingMode` `.allowed` (the default), `.disallowed` or `.required`, set as a profile modifier or through `GenerationOptions(toolCallingMode:)`. With `.required` "the model is essentially in a while loop", so provide an exit condition. The transcript policy is `transcriptErrorHandlingPolicy` `.revertTranscript` (the default) or `.preserveTranscript`. `transcript` is now settable, but only while `isResponding` is false — [documented, fetched 2026-09-26; 242] [242](https://developer.apple.com/videos/play/wwdc2026/242/)
- Orchestration: "baton-pass" (profiles share the full transcript) versus "phone-a-friend" (a tool spawns a short-lived child session with an isolated transcript, and the parent answers). A Skills type for "procedural context loading" lives in the utilities package — [documented, fetched 2026-09-26; 242] [242](https://developer.apple.com/videos/play/wwdc2026/242/); [utilities package](https://github.com/apple/foundation-models-utilities)
- Lab 8121 on managing a small window: after a tool's output has been used, "you may want to go back and drop the tool call and the tool output… once you have the answer, that's really all you need". The summary adds: keep "prompts and tool definitions lean — every tool definition and instruction consumes the shared budget… summarize or chunk long inputs, and only include the tools relevant to the task". Engineers in the same lab also advised "don't let the single session do too many things. Just break it apart"; each independent task gets "the whole context window". A phone-a-friend call to the same model "gives you an extra context window" — [documented, fetched 2026-09-26] [8121](https://developer.apple.com/videos/play/wwdc2026/8121/)
- Lab 8121, on filling the window: "if I let the model fill up its full context size… maybe there's a lot of stuff in there that's no longer relevant. And maybe the model gets a little bit distracted by it", so "evaluations are critical… knowing how much to remove, how much to condense" — [documented, fetched 2026-09-26] [8121](https://developer.apple.com/videos/play/wwdc2026/8121/)
- TN3193 (current; last revised 2026-03-31) holds the written token-budget guidance. A token is about 3–4 characters in Latin-script languages and about 1 character in CJK. "All the input and response… contribute tokens", including tool schemas, tool outputs and Generable schemas. "Split a large task into multiple language model sessions" (chunk, summarize, then combine). Aim for "a maximum of 1–3 paragraphs for prompts and instructions". Use `maximumResponseTokens` "only… to protect against unexpectedly verbose responses", because hard limits can produce malformed output — [documented, fetched 2026-09-26] [TN3193](https://developer.apple.com/documentation/technotes/tn3193-managing-the-on-device-foundation-model-s-context-window)
- Session 299: a reused session "can exhaust the session's context window mid-run which will throw an error", so "make sure your instructions… [are] self-contained" — [documented, fetched 2026-09-26] [299](https://developer.apple.com/videos/play/wwdc2026/299/)

## 3. The context-window contradiction: who says what for the shipping iOS 27 model

### Takeaway
**No Apple source says the on-device model has a 32K context.** Every Apple source that mentions 32K (spoken "32,000"; `contextSize` 32768) attributes it to the PCC server model. For the on-device model, Apple's written documentation current after release says **4K**. That covers the capability table in the PCC article, which matches what the repository recorded on 2026-09-10, and TN3193's "4096 tokens per session", although TN3193 was last revised on 2026-03-31. Apple engineers at the June labs said the iOS 27 on-device window is "the same as it was before. It's 4096". **But Apple's own WWDC26 sample code twice shows 8192.** Session 319 has `SystemLanguageModel().contextSize // 4096 on 26.0 // 8192 on 27.0 (newer devices)`, and session 241 has `// 8192`. iOS 27 also added `SystemLanguageModel.variant`, with `.core3` ("AFM 3 Core.") and `.coreAdvanced3` ("AFM 3 Core Advanced."). So the on-device backing model, and plausibly its window, can differ by device. Reasoning is "Not supported" on-device in Apple's current table. The authoritative value at runtime is `contextSize`, which Apple tells developers to read "to adapt your app to the hardware it's running on".

Neither this pass nor, apparently, Apple's docs states the shipped per-variant value.

## 6. What Apple says developers must re-test when the on-device model changes, and migration guidance

### Takeaway
Apple's instruction is explicit and repeated. The on-device model changes with the OS (iOS 26.4 in February 2026, then iOS 27), so "test your prompts with the new model to verify your app's behavior" and "If necessary, update and maintain prompts for each model version". The way to do that is the Evaluations framework, gated on OS version. Apple engineers said the on-device model changes only with an OS update, "not… silently", while the server model is "more complicated". Apple published no prompt-migration guide for iOS 26 prompts beyond this.

### Cited Findings
- June 2026 updates entry (covers iOS 27): "Use the latest on-device SystemLanguageModel that follows instructions more accurately and produces better results, including in complex scenarios. Because the model changes when a person updates to iOS 27, iPadOS 27, macOS 27, and visionOS 27, test your prompts with the new model to verify your app's behavior." — [documented, fetched 2026-09-26] [Foundation Models updates](https://developer.apple.com/documentation/updates/foundationmodels)
- February 2026 updates entry (iOS 26.4): "Use the latest on-device large language model that improves instruction-following and tool-calling abilities. Because the model changes when a person updates to iOS 26.4… test your prompts with the new model to verify your app's behavior. If necessary, update and maintain prompts for each model version." The same entry added the improved guardrails, `tokenCount(for:)` and `contextSize` — [documented, fetched 2026-09-26] [Foundation Models updates](https://developer.apple.com/documentation/updates/foundationmodels)
- Lab 8016, asked about silent model updates regressing tuned prompts: "the best thing you can do right now is check based on the OS version… The on device model really only updates as part of an OS update… But the server model is more complicated… assume that these models will update over time both on device and server… when a new OS update comes out… rerun your evaluation… It should be part of your test suite… look at… a run that ran on the old version of the OS and the new version." The panel also asked developers to report use cases that regress "during the beta period" — [documented, fetched 2026-09-26] [8016](https://developer.apple.com/videos/play/wwdc2026/8016/)
- Session 319: "You may be surprised how well the on-device model performs at certain tasks, especially with the updated model this year. But the only way to know is by evaluating." — [documented, fetched 2026-09-26] [319](https://developer.apple.com/videos/play/wwdc2026/319/)
- Session 242: "different models have different caching behavior and the only way to be certain is by measuring" with the Foundation Models Instrument. Transcript rewriting can "confuse the model", so "use the Evaluations framework to create eval sets and quantify the effect of context engineering strategies" — [documented, fetched 2026-09-26] [242](https://developer.apple.com/videos/play/wwdc2026/242/)
- Session 335: comparative evaluation in Xcode 27 ("control vs experimental", "one change at a time"); "watch for drift" between the judge and humans (Cohen's kappa target 0.6 in the demo) — [documented, fetched 2026-09-26] [335](https://developer.apple.com/videos/play/wwdc2026/335/)
- Guardrails changed across versions: false positives were reduced in 26.4, with "even more improvements in iOS 27". Lab 8121 said "Guardrails were substantially improved this year" — [documented, fetched 2026-09-26] [241](https://developer.apple.com/videos/play/wwdc2026/241/), [8121](https://developer.apple.com/videos/play/wwdc2026/8121/)
- Session 243: tokens per second can "catch regressions after changes" — [documented, fetched 2026-09-26] [243](https://developer.apple.com/videos/play/wwdc2026/243/)
- TN3193's written token guidance was last revised 2026-03-31, for the 26.4 APIs, and has not been updated for iOS 27 — [documented, fetched 2026-09-26] [TN3193](https://developer.apple.com/documentation/technotes/tn3193-managing-the-on-device-foundation-model-s-context-window)

### Inferences
- For OpenIntelligence the re-test surface on an OS model change covers five things. (1) Every prompt and instruction template, including the compression and fact-bank prompts. (2) Tool-calling behaviour and trajectories, since tool calling was explicitly improved and `ToolCallingMode` is new. (3) Guardrail and refusal rates, which changed in both 26.4 and 27. (4) Token accounting and budgets: `contextSize` may be 4096 or 8192 by device, and character-per-token heuristics may no longer hold. (5) KV-cache and latency behaviour once any history-rewriting is introduced. Apple's recommended gate is an Evaluations suite keyed to OS version and run on device.
- The app's shipped 5.4 prompts were presumably tuned on the iOS 27 model, given the 2026-09-24 ship date, but the app must also run on 26.x devices whose model differs (26.0 vs 26.4 vs 27). Apple's "maintain prompts for each model version" wording sanctions per-version prompt variants.

### Gaps
- Apple publishes no runtime model-version identifier. `variant` distinguishes Core from Core Advanced but not model revisions within an OS, and the lab said to use the OS version.
- Apple gives no specific migration checklist for prompts tuned to the iOS 26 model, beyond "test your prompts" and "update and maintain prompts for each model version".
- Apple gives no documented notice mechanism for PCC server-model updates ("more complicated", per the lab).
